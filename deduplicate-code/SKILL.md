# Deduplicate Code

## Process

```bash
art-dupl --semantic --sort total-tokens -t 22 \
  --exclude-pattern "**/generated/**" \
  --exclude-pattern "**/generatedconnect/**" \
  --exclude-pattern "**/internal/generated/**" \
  --exclude-pattern "**/internal/api/openapi*" \
  --exclude-pattern "**/persistence/db/sqlite/**"
```

1. Run the command above to find clone groups
2. For **handwritten code** (non-generated): De-duplicate by extracting shared helpers or inlining small functions
3. For **generated code** (protobuf, connect-go, sqlc, etc.): Add exclusion patterns - do NOT modify generated files marked "DO NOT EDIT"
4. Get it DOWN TO ZERO at threshold 50

**Threshold selection**:
- **50 (default)**: Industry-standard threshold — catches meaningful duplication
- **40**: Stricter — catches more clones but may include acceptable structural similarities
- **15**: Aggressive — catches incidental patterns (function signatures, error returns) that are Go idioms, not duplication

## Generated Code Guidance

Generated files (marked "DO NOT EDIT" or "Code generated by") must be excluded:
- protobuf/connect-go services: `--exclude-pattern "**/generatedconnect/**"`
- sqlc database code: `--exclude-pattern "**/persistence/db/sqlite/**"` (NOT under `generated/`)
- stringer/mockgen output: Already excluded by `**/generated/**`
- OpenAPI/Swagger generated code: `--exclude-pattern "**/internal/api/openapi*"`

If clones appear in generated code:
1. Add appropriate `--exclude-pattern` for that path
2. Do NOT attempt to modify generated files
3. Run again to verify ZERO

## Test Code Guidance

Test files (*_test.go, tests/) should be scanned like any other code. Only exclude them after reviewing the clones:

**Refactor when duplicated:**
- Shared test helpers (setup, teardown, fixtures)
- Identical HTTP handler test boilerplate (router, recorder, request creation)
- Repeated test data builders or factory functions
- Copy-pasted assertion sequences that could be a custom matcher

**Accept when idiomatic:**
- Table-driven test tables (similar shape, different data)
- Ginkgo/Gomega assertion patterns (`Expect(err).ToNot(HaveOccurred())`)
- Standard per-test setup/teardown that differs by one line

Do NOT blanket-exclude test files. Review clone groups and extract shared helpers where the duplication is real maintenance burden.

## ADR Policy (Project-Specific)

The GmbHG project has a nuanced duplicate code policy (see `docs/adr/001-duplicate-code-policy.md`):

**Accept Duplication If:**
- Different business rules (law checkers, domain logic)
- Different test scenarios (test helpers, test data)
- Type-safe abstractions (generic helpers used correctly)
- Readability benefit (clearer than abstraction)
- Domain-specific logic (different SQL queries, different sorting)

**Eliminate Duplication If:**
- Identical implementation (duplicate functions with same logic)
- No type-specific behavior (pure code repetition)
- Maintenance burden (multiple functions for same purpose)

**Note**: Clone detection tools will flag intentional duplication. Use judgment — structural similarities in test code, HTTP handlers, and repository implementations are often acceptable patterns.
