## File layout & naming

A Ginkgo suite lives in a Go package's test files. Two roles:

| File                  | Purpose                                                         | Generated by       |
| --------------------- | --------------------------------------------------------------- | ------------------ |
| `<pkg>_suite_test.go` | Bootstrap: `RegisterFailHandler` + `RunSpecs`. One per package. | `ginkgo bootstrap` |
| `<subject>_test.go`   | Specs for one subject (e.g. `book_test.go` for `Book`).         | `ginkgo generate`  |

- Use a **black-box test package** (`package books_test`) so tests exercise the public API the way a real caller would. This keeps specs honest about the user-facing surface.
- Name spec files after the **subject under test**, not the feature: `book_test.go`, not `weight_test.go`. One file per type/subject.
- Mirror the production layout: a `service/order.go` gets a `service/order_test.go`.

## Suite bootstrap file

Every package needs exactly one `<pkg>_suite_test.go`. It is the bridge between `go test` and Ginkgo.

```go
package books_test

import (
	"testing"

	. "github.com/onsi/ginkgo/v2"
	. "github.com/onsi/gomega"
)

func TestBooks(t *testing.T) {
	RegisterFailHandler(Fail)
	RunSpecs(t, "Books Suite")
}
```

- `RegisterFailHandler(Fail)` wires Ginkgo failures into `go test`.
- `RunSpecs(t, "Books Suite")` runs every `Describe`/`Context`/`It` in the package.
- Generate with `ginkgo bootstrap`. Add `--nodot` to avoid dot-imports (then prefix calls with `ginkgo.` / `gomega.`).

## Spec containers

Specs are nested containers. Read top-down as a sentence: _"Book, when it has no author, is considered invalid."_

```go
var _ = Describe("Book", func() {
	var book *books.Book

	BeforeEach(func() {
		book = &books.Book{Title: "Les Miserables", Author: "Victor Hugo", Pages: 1463}
	})

	Context("when the book is long", func() {
		It("is over 300 pages", func() {
			Expect(book.Pages).To(BeNumerically(">", 300))
		})
	})

	When("the book has no author", func() {
		BeforeEach(func() { book.Author = "" })

		It("is considered invalid", func() {
			Expect(book.IsValid()).To(BeFalse())
		})
	})
})
```

| Container          | Use for                                                                      |
| ------------------ | ---------------------------------------------------------------------------- |
| `Describe`         | The subject under test (a type or cohesive group of behaviors).              |
| `Context` / `When` | A scenario or precondition that changes behavior. Indented under `Describe`. |
| `It`               | One observable behavior — a single assertion focus. Read it as a sentence.   |

- `Context` and `When` are aliases; pick one and use it consistently within a file.
- Write `It` strings as **behavior statements** ("returns the author's last name"), not test mechanics ("checks the field").

## Setup / teardown nodes

| Node             | Runs                                        | Typical use                                                     |
| ---------------- | ------------------------------------------- | --------------------------------------------------------------- |
| `BeforeEach`     | Before each `It` in the same or child scope | Construct the subject, seed state                               |
| `JustBeforeEach` | After all `BeforeEach`, right before `It`   | The act of creating/invoking (kept separate from fixture setup) |
| `AfterEach`      | After each `It`                             | Reset env vars, close resources                                 |
| `BeforeSuite`    | Once before the whole suite                 | Start a DB, seed shared fixtures                                |
| `AfterSuite`     | Once after the whole suite                  | Tear down shared resources                                      |

Keep setup in `BeforeEach` so each `It` gets a **fresh, isolated** subject — mutations in one spec never leak into another. This is what makes specs reliable under parallel execution.

## Gomega assertions

Gomega is Ginkgo's matcher library. `Expect(actual).To(matcher)` is the core form.

```go
Expect(book.AuthorLastName()).To(Equal("Hugo"))
Expect(err).NotTo(HaveOccurred())
Expect(book.AuthorFirstName()).To(BeZero())        // zero-value of the type
Expect(book.Pages).To(BeNumerically(">", 300))
Expect(book.Categories()).To(ContainElement("novel"))
Expect(book.Categories()).To(HaveLen(3))
Expect(output).To(MatchRegexp(`order-[0-9]+`))
```

| Matcher             | Passes when…                                               |
| ------------------- | ---------------------------------------------------------- |
| `Equal(x)`          | actual == x (deep equal)                                   |
| `BeNil()`           | actual is nil                                              |
| `BeZero()`          | actual is the zero-value of its type                       |
| `HaveOccurred()`    | actual is a non-nil error                                  |
| `HaveLen(n)`        | collection length is n                                     |
| `ContainElement(x)` | collection contains x                                      |
| `MatchRegexp(re)`   | string matches the regexp                                  |
| `Succeed()`         | a non-error actual is nil (for funcs returning error only) |

For async code, use the **eventually/consistently** matchers instead of sleeps:

```go
Eventually(func() int { return queue.Size() }).Should(Equal(10))
Consistently(func() bool { return svc.Healthy() }).Should(BeTrue())
```

## Table-driven specs

When many inputs share one behavior shape, use `DescribeTable` + `Entry` to avoid copy-paste:

```go
DescribeTable("categorizing by page count",
	func(pages int, expected Category) {
		b := &books.Book{Pages: pages}
		Expect(b.Category()).To(Equal(expected))
	},
	Entry("a short story", 24, CategoryShortStory),
	Entry("a novel", 1200, CategoryNovel),
)
```

Each `Entry` is its own spec — failures point at the exact case, and the table reads as input → expected output.

## Focus & pending

During development you can narrow what runs. **These must be removed before committing** — a stray focus silently skips the whole suite.

| Prefix / decorator              | Effect                                         |
| ------------------------------- | ---------------------------------------------- |
| `FDescribe` / `FIt` / `Focus`   | Run **only** these specs, skip everything else |
| `PDescribe` / `PIt` / `Pending` | Mark as pending — skipped, not failed          |
| `XDescribe` / `XIt`             | Same as Pending (skip)                         |

CI should fail on committed focus; run `ginkgo unfocus` to strip the `F` prefixes mechanically.

## Running tests

Ginkgo specs are standard `go test` files, so both runners work:

```bash
# Plain go test — no extra tooling required
go test ./...

# Ginkgo CLI (richer output, parallel by default)
ginkgo                       # run all suites in the current dir
ginkgo ./pkg/...             # run specific packages
ginkgo -p                    # run specs in parallel across cores
ginkgo --procs=4             # pin a process count
ginkgo --focus="checkout"    # run only specs whose description matches
ginkgo --skip="integration"  # skip matching specs
ginkgo --label-filter="unit && !slow"   # filter by Label() decorators
ginkgo --cover --coverprofile=coverage.out
ginkgo --flake-attempts=3    # retry flaky specs up to N times
ginkgo -v --trace            # verbose with full stack traces
```

Generate boilerplate:

```bash
ginkgo bootstrap              # creates <pkg>_suite_test.go
ginkgo generate book          # creates book_test.go
```

## Common mistakes

- **Asserting implementation, not behavior.** `It("sets the private field")` couples the spec to internals. Prefer `It("reports the weight in grams")` — what the user observes.
- **Shared mutable state across specs.** Construct fresh subjects in `BeforeEach`; never share a pointer across `It` blocks. This is the #1 cause of order-dependent failures.
- **Committed focus.** `FIt` makes the suite green while skipping everything. Run `ginkgo unfocus` or grep for `^F` before committing.
- **Dot-import collisions.** If `--nodot` is used, every call needs the `ginkgo.`/`gomega.` prefix; mixing styles in one file causes compile errors.
- **Sleeping instead of polling.** Use `Eventually(...).Should(...)` for async assertions instead of `time.Sleep` + `Expect`.
