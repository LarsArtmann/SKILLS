Adoption signal was shipped on n=1 evidence

stack-selection/SKILL.md §Phase 1 (before fix)

The skill told every future reader that meta list --tags <name> reveals a library's consumers, "verified" by one example (cmdguard→timesheets). Measured this evening: of 58 lib-tagged projects, exactly one lib name appears as a tag anywhere in the 279-project inventory. The signal I shipped as a rule is noise. The real signal was sitting next to it the whole time: go.mod grep — grep -l "larsartmann/<name>" ~/projects/*/go.mod — which measures cmdguard at 27 consumers, go-output at 43, go-cqrs-lite at 45.

Fixed same session: Phase 1 now leads with the go.mod grep (numbers cited), demotes meta tags to "sparse secondary signal — an empty result means nothing". Status report corrected with a note that it was corrected.

CHANGELOG.md, session status report

Shipped "~60 libs in 10 categories". Counted programmatically after the fact: 67 lib rows in 11 categories.
