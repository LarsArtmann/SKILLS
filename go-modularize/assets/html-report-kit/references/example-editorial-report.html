00Summary

The kit replaced its Tailwind-default palette (indigo on slate-900) with the Bauhaus system: primary colors on warm paper (light) or graphite (dark). The component vocabulary is unchanged — every class name consumers already use still works.

The bottom line Swap-in upgrade for all 11 consumer skills. No markup changes required. Run scripts/sync-html-kit.sh to propagate.

◆What's already excellent

The bones of the kit were sound; only the skin needed work.

+
Unified token vocabulary Both templates now share semantic names. The split brain (--rose vs --coral, --bg-elevated vs --bg-card) is gone.
+
color-mix() eliminates drift Glow/light variants derive on demand from solid colors. ~8 redundant tokens removed.
+
Backward-compatible aliases Old token names (--rose, --coral, --bg-card, --ink) still resolve. Zero consumer breakage.

01Findings

What the audit surfaced during the migration.

Fixed · High impact

Palette was unoriginal

html-report-kit/assets/*.html

The prior palette used Tailwind's stock indigo (#6366f1) on slate-900 (#0f172a) — the most recognizable AI-generated combination in production.

Fix: adopted Bauhaus Primary colors (red/blue/yellow) on neutral grounds. Form follows function.
Fixed · Medium impact

Token vocabulary was split between templates

html-output-guide.md §CSS Design Tokens

Dark used --bg-elevated, --rose, --emerald. Light used --bg-card, --coral, --teal. Same concepts, different names — a split brain.

Nice to have · Low impact

Consider documenting a strict CSP example

html-output-guide.md

Templates are inline-style only (plus optional progressive-enhancement script). A strict Content-Security-Policy example would help security-conscious users.
